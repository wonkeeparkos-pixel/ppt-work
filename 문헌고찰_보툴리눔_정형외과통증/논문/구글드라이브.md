# 구글 드라이브 — 같은 구조로 만들어 둔 폴더

이 저장소의 `논문/` 폴더와 **똑같은 13개 부위별 폴더**를 구글 드라이브에도 만들어 뒀다.
드라이브 쪽에는 폴더마다 `— 논문목록` 구글 문서가 들어 있고, 논문별 제목·용량·핵심 수치와
**클릭 가능한 다운로드 링크**가 정리돼 있다. PDF는 그 폴더에 그대로 끌어다 놓으면 된다.

## 발표 파일은 링크로만 뒀다

드라이브 API는 파일 내용을 통째로 실어 보내야 한다. PPTX 9.5 MB·PDF 9.7 MB는 그 한도를
크게 넘어서 올리지 못했다. 대신 `발표자료` 폴더의 「여는 법」 문서에 **아티팩트 링크와
공개 저장소 직접 다운로드 링크**를 넣어 뒀다 — 눌러 받은 뒤 그 폴더에 끌어다 놓으면 된다.

저장소가 공개라서 아래 형태의 링크가 브라우저에서 바로 받아진다(네 파일 모두 200 확인).

```
https://github.com/wonkeeparkos-pixel/ppt-work/raw/<브랜치>/문헌고찰_보툴리눔_정형외과통증/<파일명>
```

## PDF가 비어 있는 이유

이 저장소를 만든 원격 환경은 논문 도메인이 네트워크 정책으로 차단돼 있다(확인함).

```
www.ebi.ac.uk        CONNECT tunnel failed, 403
pmc.ncbi.nlm.nih.gov CONNECT tunnel failed, 403
doi.org              CONNECT tunnel failed, 403
```

그래서 PDF는 두 가지 방법으로 채운다.

1. 드라이브의 `— 논문목록` 문서에서 링크를 눌러 받고, 같은 폴더에 끌어다 놓기
2. 로컬에서 `python3 scripts/fetch_papers.py` — 오픈액세스 논문은 자동으로 채워진다

오픈액세스로 바로 받을 수 있는 것은 5편이다 — 00번(기전 리뷰), 04번(손 이긴장증),
07번(이상근 체계적고찰), 10번(족저근막염 메타분석), 12번(면역원성 리뷰).

## 폴더를 다시 만들거나 옮길 때

부위 구성이 바뀌면 `scripts/papers.py`의 `FOLDERS`·`PAPERS`를 고치고
`python3 scripts/build_paper_folders.py`를 다시 돌린다. 드라이브 쪽은 수동으로 맞춘다
(드라이브 폴더 ID는 위 표에 적어 뒀다).

## 드라이브 문서를 만들 때 주의 — 표를 쓰지 말 것

드라이브의 마크다운 → 구글 문서 변환기는 **표 셀 안의 마크다운을 처리하지 못한다.**
셀 안에 링크나 굵은 글씨를 넣으면 `\[제목\](url)` 처럼 문자 그대로 찍혀서 링크가 죽는다.
제목(`##`)과 불릿(`- `)으로 쓰면 링크가 정상으로 살아난다.

이 API에는 파일 수정·삭제 도구가 없다. 잘못 만든 문서는 지울 수 없으니
**만들기 전에 형식을 확인**하고, 만든 뒤에는 `read_file_content`로 링크가 살았는지 검증한다.
